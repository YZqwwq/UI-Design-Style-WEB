# 管理项目 Skills

由 Agent 按以下约定完成接入与登记。所有已登记 skills 最终按路径读取；来源差异在接入阶段处理，不要求日常任务重新定位。尚未提供批量安装脚本、来源可信性校验或自动版本同步。

## 收录触发

- 用户提供名称或路径，要求用某个 skill 处理项目任务，或 Agent 已选定该能力用于任务时，先查地图，未登记则执行下述接入步骤。可先读取源入口判断身份与适用性；正式使用时转向已登记的全局入口或项目副本。
- “查看这个 skill，帮项目排查问题”属于实际任务使用；“评价这个 skill 的设计”仅是审阅对象，不自动接入。仅提到名称、发现某目录或加载了可用能力列表，也不触发批量收录。
- 项目接入约定下的首次使用包含收录动作，无需再要求用户说“添加”。明确的只读、不复制或不登记要求优先；不能写入时说明缺口，不声称收录完成，必要的读取与原任务仍可继续。
- 登记代表可再次选择的能力，不是常驻规则。规范类与工具类均按需使用；文本偏好的持久化仍按独立授权判断。
- 已登记则核对入口后复用，不重复复制；相同名称但不同来源按冲突处理，不用名称相同直接覆盖。来源不明、依赖缺失或权限不足时说明具体障碍。

## 区分文本规则与 skills

- 轻量文本规则描述项目偏好、方向约束和参考指引，放在 `.project-manager/rule/`；管理这些内容时读取 [文本规则管理](references/manage-text-rules.md)。不把偏好包装成 skill，也不把完整 skill 正文展开为文本规则。
- 规范类 skill 提供专业要求和工作方法，工具类 skill 提供具体自动化能力。两类均按需读取使用，统一登记到 `.project-manager/skill/index.md`。
- 能力地图记录名称、类型、职责摘要、必要适用条件和最终路径；`AGENTS.md` 只保留地图入口与检索约定，不逐项列出 skills。
- 分类与安装位置无关，全局安装不代表项目自动采用。接入或调整时阅读 skill 后整理自然语言摘要，不要求日常任务遍历目录。

## 接入位置

| 来源 | 接入方式 | 最终登记入口 |
| --- | --- | --- |
| 已确认的本地全局安装 | 保留原位置，不复制、不修改源文件 | 实际可读取的绝对路径 |
| 非全局 skill 文件夹，包括项目其他位置的 skill | 复制完整能力包到 `.project-manager/skill/<名称>/`，保留原件 | 项目相对路径 `.project-manager/skill/<名称>/SKILL.md` |
| 独立 skill 文件 | 在统一目录建立对应文件夹，以 `SKILL.md` 作为入口，并带上必要依赖 | 项目相对路径 `.project-manager/skill/<名称>/SKILL.md` |
| 已在统一目录中的 skill | 直接核对并登记，避免自我复制或重复嵌套 | 已有项目相对路径 |

`.project-manager/skill/` 统一管理项目接入的所有非全局 skills，包括管理器分发的规范。不是全局安装的外部文件夹，不作为长期登记入口；复制后使用项目副本。不要把“位于项目外”直接当成“全局安装”，应依据已知安装位置和来源判断，确有歧义时再询问。

## 接入步骤

1. 根据用户要求确定要接入的 skill、职责类型及范围，不自动登记环境中所有可用 skills。检查入口并读取其说明，确定能力包边界和引用资源。
2. 按上表确定最终位置。复制前检查源与目标是否相同、目标是否已存在；同名不直接覆盖。不同 skill 使用可区分目录；同一 skill 的更新按当前授权处理，保留项目已有定制，不能确定替换范围时说明差异。
3. 非全局 skill 复制完整能力包，保留 `references/`、`scripts/`、`assets/` 等所需资源及其相对结构，不复制外层无关项目、仓库历史或缓存。独立文件若缺少引用资源，先补足可获取的依赖，无法补足时说明缺失，不宣称接入完成。
4. 检查副本中的相对引用、绝对引用和符号链接，不能通过链接继续依赖散落的非全局原件。属于能力包的依赖应一并复制并按需调整项目副本引用；系统命令、运行时和外部服务等环境依赖如实保留说明，不无限追拷。
5. 确认最终入口及必要文件可读取后，再把最终路径登记到统一能力地图。接入不要求执行 skill 内的业务脚本，不因复制而扩大任务授权。
6. 报告最终路径、登记类型和未满足的环境条件。尚未实现的能力在摘要中标明，不描述成可执行的完整能力。

## 维护与失效

- 项目副本成为后续使用和维护的入口；不回写外部原件，原件变化不自动同步。只有用户要求更新或已有相应授权时才更新副本。
- 全局 skill 只维护项目登记，不因本项目使用而修改、删除或搬迁全局源文件。路径失效时报告缺失，不默默选择其他同名 skill，也不擅自改为项目副本。
- 新增、移除、替换 skill 时同步维护对应登记；调整分类时更新原条目，避免重复登记。取消登记不默认删除源文件或项目副本，文件清理由当前明确任务决定。
- Skills 更新只维护独立能力地图，不把摘要写回 `AGENTS.md`。文本规则地图或公共加载约定变化时，同步维护实际优先入口 `AGENTS.override.md`（若存在），保留无关规则。
- 已有非全局外部引用在本次涉及接入或迁移时，先完成复制和核对，再切换登记路径，不默认遍历或迁移全部 skills。
- 根据用户当前指示与已有授权变更；临时调用不自动成为长期规范，整理摘要不自行扩大适用范围。

## 旧结构迁移

用户要求升级已有项目时，读取现有入口、旧 `tools.md` 及能力地图，先合并规范类和工具类条目到 `skill/index.md`，保留用户的路径、摘要和适用范围，不以模板覆盖。再移除入口中已迁移的 skill 摘要，保留项目原有规则；只有确认旧目录没有独有内容且引用已更新后才移除旧 `tools.md`。旧入口中的纯文本偏好按文本规则管理流程迁入 `rule/`，不把专业 skill 全文转换成轻量规则。初始化脚本只补缺和提示，不自动完成旧内容迁移。

管理能力更名：`skill-rules` → `manage-skills`，`document-rules` → `manage-documents`。升级时保留目标项目定制并更新地图及引用，确认旧目录无独有内容后再移除；不靠保留两套同义 skill 解决迁移。
