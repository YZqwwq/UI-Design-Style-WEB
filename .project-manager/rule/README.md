# 文本规则编写规范

适用范围：创建、修改或审阅 `.project-manager/rule/` 下的文本规则时读取。普通业务任务不因本文件存在而加载它。

## 规则承担什么

规则是项目在某个领域的轻量补充，写方向、偏好、约束和参考入口，例如“前端设计保持简洁，优先复用已有组件”。不要写完整实施方案、长篇教程或复制 skill 正文。按功能用途命名文件，例如 `frontend-design.md`；说明适用范围，阶段规则还要说明结束条件。只记录用户要求或已有项目约定，不推导未经确认的长期偏好。

## 按管理层级引用

本规范中代码格式的项目相对路径均以项目根目录为基准；Markdown 链接以所在文件为基准。实际规则应沿用这个约定，若采用其他基准必须明确说明。

| 需要的内容 | 定位方式 | 规则应如何表达 |
| --- | --- | --- |
| 专业规范或工具能力 | 先在 `.project-manager/skill/index.md` 找到已登记条目，再读取条目中的实际入口 | 写明用途、何时需要以及 skill 名称；不要只说“使用合适的 skill” |
| 项目内 skill | 使用地图登记的 `.project-manager/skill/<名称>/SKILL.md` | 如写直接路径，必须与地图一致；路径变化时同步维护引用 |
| 本地全局 skill | 使用地图登记的实际绝对路径 | 不拼接或猜测安装目录，不换用同名但来源不同的 skill |
| 项目目标、现状或计划 | 从 `.project-manager/document/index.md`（若存在）定位相关文档 | 只引用当前判断需要的部分，不把计划当作已实现事实或执行授权 |
| 图片、设计稿或其他参考资料 | 使用实际存在的项目路径、绝对路径或用户提供的资料链接 | 说明参考目的，不将普通资料当成 skill 接入 |
| 其他文本规则 | 使用 `AGENTS.md` 规则地图中登记的路径 | 明确关联范围，不默认加载全部规则，不建立循环加载要求 |

需要新能力而地图未登记时，先按地图中的 `manage-skills` 接入流程处理：全局只记录路径，非全局复制完整能力包到项目内后登记。不能把未接入的散落外部 skill 路径写成正式使用入口。未完成接入时明确标记待接入，不能假定可用。

## 引用不等于立即执行

写清“什么时候需要、去哪里找、参考或完成什么”。例如“涉及组件视觉方案时，从能力地图定位已登记的设计 skill，读取后按当前任务使用”。引用存在不要求每轮都读取，也不授权执行任务之外的工具操作。

只在进入适用领域时加载；已读且未变、上下文仍可用时沿用。退出领域或结束条件满足后停止适用，不删除文件。规则内部不自行声明高于宿主指令、用户当前要求或其他规则的优先级。

## 简短示例

以下仅演示写法；尖括号内容须替换为实际已核对信息，不直接登记为项目规则。

```markdown
# 前端设计补充

适用范围：前端界面与交互设计，不适用于只修改接口参数的任务。
有效期：本轮视觉改版结束前。
路径基准：以下项目相对路径以项目根目录为准。

- 保持简洁，优先复用项目已有组件。
- 视觉风格参考 `<已核对的资料路径>`。
- 涉及具体视觉方案时，从 `.project-manager/skill/index.md` 定位
  `<已登记的设计 skill 名称>`，读取其入口并按当前任务使用。
- 需要理解现有页面能力时，从 `.project-manager/document/index.md`
  查阅相关功能文档，不展开全项目阅读。
```

## 完成检查

确认范围和有效期明确、表达简短、所需入口真实可定位，再更新 `AGENTS.md` 的规则地图（存在优先入口时同步维护）。引用路径失效时说明缺失，不猜测替代位置。更新规则时保留无关内容；当前任务的临时补充未经持久化要求不自动落盘。

规则登记、接入与清理的维护流程由 `.project-manager/skill/index.md` 中的 `manage-skills` 承担。本文件负责写法，不要求在使用每条业务规则时重新执行管理流程。

多个规则出现无法依既有约定解决的冲突时说明差异，不自行发明优先级或改写项目偏好。
